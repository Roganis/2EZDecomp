# Obj402860::m403940 @0x403940 (986 bytes) and step @0x4029b0 (~900 bytes) — survey 2026-08-18

The cell-table "refresh" every writer tail-calls (47 call sites, the biggest
well-modelled STUB on the spine) and the single-step cursor advance seek
@0x402d60 loops on. Both are the SAME shape: a per-row tween player over the
head's table (Obj402860Head: rowCount @+8, fc @+0xc, rows @+0x10 stride 0x4f0
= Obj402860Row {count, f4, data[314]}).

What m403940 does (decoded so far):
- `if (head == 0) return 0`; `if (f20c >= head->fc)` (isDone) `{ if (f4 == 0) return 0; reset(); }`.
- for each row r < head->rowCount: `row = &head->rows[r]`; skip when
  `[row+0x4e8]` (== head+0x4f8+r*0x4f0) is 0 or the cursor `buf[r]` (this+0xc,
  int per row) is -1. `key = row->keys + cursor*0x7c` where `row->keys` is the
  pointer at row+0x4dc (`[ecx+0x4ec]` from the head-relative base) - a table
  of 0x7c-byte KEYFRAMES {int time @0, int flags @4, float ch[29] @8..0x7c?,
  float @0x58 speed, int @0x54 wrap mode, ...}; `dt = f8 - key->time` (this+8
  = the current frame counter), skip if negative.
- `out = head + r*0x74 + 0x27810` — the per-row OUTPUT block (29 floats).
  If dt == 0 and the next key's time == f8 (`[edx+0x7c]`): advance the cursor
  (`buf[r]++`, and when it passes row->count-1 (`[row+0x4d8]`) set it to -1
  and `f20c++`), and step to the next key.
- key->flags & ... : `if ([edx+4] == 0)` copy the key's 29 floats straight to
  `out` (rep movs 0x1d) and to a stack copy, then if the cursor is not -1 and
  the next key's time equals this key's, cursor++ (an instant key).
- else (an interpolating key): clamp `key->speed` (@0x58) `> 0x487664` to 0,
  then out[i] += key->ch[i] for the 29 channels (unrolled), copy `out` to the
  stack, and `switch (key->wrap - 1)` (jump table @0x403e08, 5 arms): the
  arms recompute a phase `out[0x48/4]` from `+= speed`, wrapping against
  `(float)row->period` (`[esp+0x10]` = the row's first int) - hold / wrap by
  subtraction / fmod via cvttss2si / ping-pong (`(dt*speed) / (period-1)`
  parity) — the classic tween wrap modes.
- then `if (f210 != 0)` … (the rest, 0x403d24.., not read: presumably the
  per-row callback / apply into the owner).

Register-heavy (xmm0..xmm3, ebx as the row counter zero, ebp = this) with a
0x80 aligned frame holding the 29-float stack copy @esp+0x18. Expect a
several-iteration sitting; read step @0x4029b0 alongside, since it shares the
row/key walk (its listing at 0x4029b0..0x402d35 has the same
`cmp [ecx+eax*1+0x4f8]` guard, `movss xmm3,[0x487644]` and the 0x1d copies).
